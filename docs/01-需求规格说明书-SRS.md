## 1. 引言

### 1.1 目的

本文档定义 **BeeBrew**（macOS 原生 Homebrew GUI 应用）MVP 版本的功能需求与非功能需求，作为架构设计、编码实现与测试验收的**唯一需求依据**。所有需求均带唯一编号（FR-xxx / NFR-xxx），后续架构师、工程师、测试工程师将引用这些编号进行可追溯性管理。

### 1.2 范围

#### 1.2.1 本次范围内（MVP）

- **软件包管理**（第 1 类命令）：安装 / 卸载 / 升级 / 详情 / 搜索 / 已安装列表（Formula + Cask）
- **Cask 基础管理**（第 3 类命令）：Cask 的安装 / 卸载 / 已安装列表
- **系统维护精简**（第 2 类命令子集）：`brew update`、`brew outdated`、`brew cleanup`
- **设置**：Homebrew 路径配置、主题切换

#### 1.2.2 本次范围外（后续版本，仅预留 P2 需求编号）

- Tap 仓库管理（`brew tap / untap`）
- 服务管理（`brew services`）
- Bundle 管理（`brew bundle`）
- 系统诊断（`brew doctor`）
- 多语言（i18n）

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| Homebrew | macOS（及 Linux）上的开源包管理器，本项目所有操作的底层执行者 |
| Formula | Homebrew 对命令行工具/库的安装描述文件，对应 CLI 工具与开发库 |
| Cask | Homebrew 对 GUI 应用（.dmg/.pkg/.zip 安装的 App）的安装描述文件 |
| Bottle | Formula 的预编译二进制包，避免源码编译 |
| Cellar | Homebrew 实际存放已安装包版本文件的目录（如 `/opt/homebrew/Cellar`） |
| Tap | 提供 Formula/Cask 的第三方 Git 仓库（如 `homebrew/core`、`homebrew/cask`） |
| Keg | Cellar 中某个包某个具体版本的安装目录 |
| Prefix | Homebrew 根目录（Apple Silicon 为 `/opt/homebrew`，Intel 为 `/usr/local`） |
| outdated | 已安装但存在更新版本的状态 |
| pinned | 被 `brew pin` 锁定的包，不参与 `brew upgrade` |

## 2. 产品概述

### 2.1 背景

Homebrew 是 macOS 最流行的包管理器，但纯 CLI 界面存在明显痛点：

1. 新手需记忆大量命令，学习曲线陡峭；
2. 已安装包缺乏直观视图，难以整体把握；
3. 依赖关系不透明，升级/卸载风险不可视；
4. Formula（命令行工具）与 Cask（GUI 应用）管理割裂；
5. 系统更新（`brew update` / `outdated`）需手动逐个命令执行。

现有参考产品 CakeBrew 已停更（最后更新 2021），功能陈旧、无法适配新版 Homebrew（4.0+）与新版 macOS。市场存在**原生、现代、活跃维护**的替代需求。

### 2.2 定位

BeeBrew 是一款 **macOS 14+ 原生桌面应用**，通过调用 `brew` CLI（JSON 输出）为 Homebrew 提供直观、高效的图形化管理界面。采用 CakeBrew 经典**三栏式布局**（左侧导航 / 中间列表 / 右侧详情），实现 Formula 与 Cask 的一站式搜索、安装、卸载、升级闭环。

### 2.3 目标用户

| 用户角色 | 特征 | 核心诉求 |
|----------|------|---------|
| 开发者（前端/后端） | 高频使用 Homebrew 装工具链 | 快速搜索安装、批量升级、依赖可见 |
| DevOps / SRE | 关注版本一致性与环境健康 | 可升级清单、批量升级、cleanup 释放空间 |
| 设计师 / 产品经理 | 不熟悉命令行，偶尔装 GUI 工具 | 零门槛 GUI 操作、一键安装 Cask |
| 技术管理者 | 关注团队环境标准化 | 环境清单快照（列表导出） |

### 2.4 设计原则

1. **原生体验**：遵循 Apple HIG，全程 SwiftUI 原生组件。
2. **信息分层**：左侧导航分类 → 中间列表浏览 → 右侧详情下钻。
3. **操作直达**：常用操作 ≤ 2 次点击，全局搜索随时可用。
4. **渐进披露**：默认精简信息，展开后显示高级选项（依赖树、版本历史）。
5. **实时反馈**：所有长耗时操作提供进度指示与结果通知。
6. **只读优先 + 显式写操作**：浏览行为不触发破坏性副作用，所有写操作（安装/卸载/升级/清理）须显式确认。

## 3. 用户故事

### 3.1 开发者角色

1. 作为**开发者**，我希望在搜索框输入包名即可实时看到 Formula 与 Cask 的匹配结果，以便快速找到并安装所需工具。
2. 作为**开发者**，我希望在「已安装」页面看到全部 Formula 与 Cask 的列表及版本，以便整体把握本地环境。
3. 作为**开发者**，我希望批量勾选多个过期的包并一键升级，以便一次性完成环境更新而不必逐个执行命令。
4. 作为**开发者**，我希望点击某个包后能看到它的版本、大小、安装路径、依赖和 Homepage，以便评估升级/卸载的影响。

### 3.2 DevOps / SRE 角色

5. 作为 **SRE**，我希望进入「更新」页面即自动执行 `brew outdated` 并展示「当前版本 → 目标版本」，以便快速决策升级范围。
6. 作为 **SRE**，我希望执行 `brew cleanup` 清理旧版本并看到释放的磁盘空间，以便回收存储。

### 3.3 设计师 / 产品经理角色

7. 作为**设计师**，我希望在不接触命令行的前提下通过搜索并点击「安装」完成 GUI 应用（Cask）的安装，以便零门槛安装日常软件。
8. 作为**产品经理**，我希望所有安装/卸载/升级操作都有明确的进度条和完成/失败通知，以便感知操作状态。

### 3.4 技术管理者角色

9. 作为**技术管理者**，我希望在设置页配置 Homebrew 路径（自动检测 + 手动指定），以便适配不同架构与安装位置的环境。

## 4. 功能需求

> 优先级约定：**P0** = 必须实现（MVP 核心闭环，缺失则不可发布）；**P1** = 应当实现（体验完整性）；**P2** = 可后续实现（预留编号，不在本次开发范围）。
> 每条需求的「CLI 映射」标注其调用的具体 brew 命令，确保可追溯与可测试。

### 4.1 P0 需求池（MVP 核心闭环）

#### FR-001 Homebrew 环境检测与路径解析

- **优先级**：P0
- **CLI 映射**：`brew --version`、`brew --prefix`、`brew config`
- **描述**：应用启动时检测本机是否安装 Homebrew，解析其安装路径（Prefix），并读取版本号。检测结果用于驱动后续所有命令的执行路径与首页状态展示。
- **验收标准**：
  1. 当 Homebrew 已安装时，应用能正确获取版本号与 Prefix（`/opt/homebrew` 或 `/usr/local`）。
  2. 当 Homebrew 未安装时，首页展示引导状态（提示安装方式与链接），且不崩溃、不执行后续命令。
  3. 路径解析支持 Apple Silicon 与 Intel 双架构。

#### FR-002 获取已安装 Formula 列表

- **优先级**：P0
- **CLI 映射**：`brew list --formula --json=v2`
- **描述**：在「已安装」页面的 Formula Tab 下，展示本机已安装的 Formula 列表，字段包括名称、当前版本、占用大小、状态（最新/可更新/已锁定）。
- **验收标准**：
  1. 列表数据与 `brew list --formula --json=v2` 输出一致（名称、版本、大小无缺失）。
  2. 加载完成耗时 < 500ms（见 NFR-001）。
  3. 空状态时展示「暂无已安装的 Formula」提示。

#### FR-003 获取已安装 Cask 列表

- **优先级**：P0
- **CLI 映射**：`brew list --cask --json=v2`
- **描述**：在「已安装」页面的 Cask Tab 下，展示本机已安装的 Cask（GUI 应用）列表，字段包括名称、当前版本、占用大小、应用图标。
- **验收标准**：
  1. 列表数据与 `brew list --cask --json=v2` 输出一致。
  2. Cask 条目展示应用图标（提取自 App Bundle）。
  3. Cask 与 Formula 在 UI 上通过 Tab 清晰隔离。

#### FR-004 Formula / Cask 分类 Tab 切换

- **优先级**：P0
- **CLI 映射**：无（纯 UI 行为，数据来源 FR-002 / FR-003）
- **描述**：「已安装」页面顶部提供「Formulas / Casks」两个 Tab，点击切换显示对应类别列表，并保留各自独立的选中状态与筛选状态。
- **验收标准**：
  1. 点击 Tab 切换内容，无闪烁、无数据串扰。
  2. 当前激活 Tab 有明确视觉高亮。
  3. 切换后右侧详情面板清空或同步到当前类别的默认状态。

#### FR-005 全局搜索 Formula 与 Cask

- **优先级**：P0
- **CLI 映射**：`brew search --json=v2 <关键词>`
- **描述**：提供全局搜索能力，输入关键词后实时匹配 Formula 与 Cask，结果展示包名、类型（Formula/Cask）、版本、描述、是否已安装。
- **验收标准**：
  1. 输入后 300ms 防抖内返回结果（见 NFR-002）。
  2. 搜索范围可切换：全部 / 仅 Formula / 仅 Cask。
  3. 结果正确标记「已安装」状态；未安装项提供「安装」入口。
  4. 空关键词时展示默认推荐（热门包）或空状态提示。

#### FR-006 安装 Formula

- **优先级**：P0
- **CLI 映射**：`brew install <formula>`
- **描述**：用户可对搜索到的或详情面板中的 Formula 发起安装操作，安装前展示确认信息（包名、版本、预计下载来源），安装中展示实时进度，安装后刷新列表并通知。
- **验收标准**：
  1. 安装前有确认步骤，明确显示目标包名。
  2. 安装过程有进度指示与可取消入口（见 FR-014）。
  3. 安装成功后 Formula 列表自动刷新且新包出现在已安装列表。
  4. 安装失败时展示错误信息与失败原因（含 CLI 原始输出可查看）。

#### FR-007 安装 Cask

- **优先级**：P0
- **CLI 映射**：`brew install --cask <cask>`
- **描述**：用户可对搜索到的 GUI 应用（Cask）发起安装，安装前确认（包名、来源 URL、大小），安装中展示下载/挂载/安装进度，安装后刷新 Cask 列表并通知。
- **验收标准**：
  1. 安装前确认弹窗展示来源 URL 与包大小。
  2. 安装成功后 Cask 列表自动刷新且新应用出现。
  3. 支持在安装完成后一键「打开应用」（可选，作为 P1 增强）。

#### FR-008 卸载 Formula

- **优先级**：P0
- **CLI 映射**：`brew uninstall <formula>`
- **描述**：用户可对已安装 Formula 发起卸载，卸载前展示确认信息（包名、将被移除的版本），卸载后刷新列表。
- **验收标准**：
  1. 卸载前有二次确认，明确列出受影响包。
  2. 卸载成功后该包从已安装列表移除。
  3. 卸载失败时保留原列表状态并展示错误原因。

#### FR-009 卸载 Cask

- **优先级**：P0
- **CLI 映射**：`brew uninstall --cask <cask>`
- **描述**：用户可对已安装 Cask 发起卸载，卸载前确认，卸载后刷新 Cask 列表。
- **验收标准**：
  1. 卸载前二次确认。
  2. 卸载成功后该 Cask 从列表移除。
  3. 卸载失败时展示错误信息。

#### FR-010 检测可升级包

- **优先级**：P0
- **CLI 映射**：`brew outdated --json=v2`
- **描述**：「更新」页面进入时自动执行 outdated 检测，列出可升级的 Formula/Cask，展示「当前版本 → 目标版本」，并在侧边栏「更新」入口展示可升级数量 Badge。
- **验收标准**：
  1. 进入「更新」页面自动触发检测，结果与 `brew outdated --json=v2` 一致。
  2. 每条记录清晰展示当前版本与目标版本。
  3. 侧边栏 Badge 数字与可升级总数一致。
  4. 无可升级包时展示「所有包均为最新」状态。

#### FR-011 升级包

- **优先级**：P0
- **CLI 映射**：`brew upgrade [<formula>|<cask>]`
- **描述**：用户可对单个或多个可升级包发起升级，升级过程展示逐项进度与完成摘要（成功/失败数量）。
- **验收标准**：
  1. 支持单个升级与「全部升级」。
  2. 升级完成后展示成功 N 项 / 失败 N 项摘要。
  3. 失败的包保留在可升级列表并可单独重试。
  4. 升级完成后已安装列表与可升级列表均刷新。

#### FR-012 批量多选操作

- **优先级**：P0
- **CLI 映射**：组合调用 FR-006 / FR-008 / FR-009 / FR-011 对应命令（一次批量操作可依次执行多个 `brew install/uninstall/upgrade`）
- **描述**：在列表页支持多选（复选框 + `Cmd/Shift` 点选 + 全选），底部展示批量操作栏，可对选中项批量执行卸载或升级。
- **验收标准**：
  1. 支持复选框多选、`Cmd` 加选、`Shift` 范围选、`Cmd+A` 全选。
  2. 底部操作栏实时显示「已选 N 项」。
  3. 批量卸载/升级前统一确认，列出全部目标包。
  4. 批量操作按顺序执行，汇总结果（成功/失败清单）。

#### FR-013 详情面板信息展示

- **优先级**：P0
- **CLI 映射**：`brew info --json=v2 <name>`、`brew deps <name>`（依赖部分）
- **描述**：选中列表项后，右侧详情面板展示完整信息：名称、描述、版本、大小、安装路径、依赖列表、Homepage、License、Tap 来源、安装时间。
- **验收标准**：
  1. 点击列表行，详情面板即时更新对应包信息。
  2. 展示字段至少包含：版本、大小、路径、依赖、Homepage。
  3. Formula 展示依赖列表；Cask 展示来源格式（.dmg/.pkg/.zip）与应用图标（Cask 不展示运行时依赖）。
  4. 未选中任何项时展示占位提示。

#### FR-014 操作进度展示与结果反馈

- **优先级**：P0
- **CLI 映射**：对 FR-006/007/008/009/011/015/016 的底层进程输出做流式解析展示
- **描述**：所有长耗时操作（安装/卸载/升级/更新/清理）统一通过进度视图展示当前进度、当前处理项、已完成项清单，并提供「后台运行」与「取消」入口；完成后触发系统通知与列表刷新。
- **验收标准**：
  1. 操作启动 < 1s 内出现进度指示（见 NFR-002）。
  2. 进度视图展示当前处理项与累计进度。
  3. 支持后台运行（操作继续进行、UI 不阻塞）与取消。
  4. 操作完成/失败触发系统通知（见 NFR 相关）。

#### FR-015 更新 Homebrew 自身

- **优先级**：P0
- **CLI 映射**：`brew update`
- **描述**：「更新」页面提供「更新 Homebrew」入口，刷新 Homebrew 与 Tap 的元数据，并显示上次更新时间。
- **验收标准**：
  1. 点击后执行 `brew update`，过程有进度/耗时展示。
  2. 完成后更新「上次更新时间」并重新触发 outdated 检测（FR-010）。
  3. 失败时展示错误原因。

#### FR-016 清理旧版本

- **优先级**：P0
- **CLI 映射**：`brew cleanup`（可用 `--dry-run` 预览，`--prune` 清理）
- **描述**：提供「清理」入口，预览可释放的旧版本缓存与磁盘空间，确认后执行清理并展示释放的空间大小。
- **验收标准**：
  1. 清理前展示预计可释放空间（基于 `brew cleanup --dry-run` 或 `--prune` 预检）。
  2. 确认后执行清理，完成后展示实际释放空间。
  3. 清理完成后刷新已安装列表与详情中的大小信息。

#### FR-017 设置 — Homebrew 路径配置

- **优先级**：P0
- **CLI 映射**：配置项影响 FR-001 路径解析（读写应用配置，不直接调 brew）
- **描述**：设置页允许用户查看并手动指定 Homebrew 安装路径，默认自动检测；手动指定时校验目录有效性。
- **验收标准**：
  1. 默认展示自动检测到的路径。
  2. 手动指定仅允许选择已存在且包含 `bin/brew` 的目录，非法路径给出校验提示。
  3. 修改后重启生效或立即重新检测，后续命令使用新路径。

#### FR-018 设置 — 主题切换

- **优先级**：P0
- **CLI 映射**：无（纯 UI 偏好）
- **描述**：设置页提供外观主题选项：跟随系统 / 浅色 / 深色，选择后即时生效并持久化。
- **验收标准**：
  1. 三种主题可切换，选择后即时生效。
  2. 主题偏好持久化，重启后保持。

### 4.2 P1 需求池（体验完整性）

#### FR-019 列表排序

- **优先级**：P1
- **CLI 映射**：无（对 FR-002/003 结果本地排序）
- **描述**：已安装列表支持按名称（A→Z）、版本、大小排序。
- **验收标准**：点击列头切换排序方向，排序结果稳定、可复现。

#### FR-020 列表状态筛选

- **优先级**：P1
- **CLI 映射**：无（结合 FR-002/003/010 结果过滤）
- **描述**：列表提供状态筛选：全部 / 可更新 / 已锁定 / 最近安装（7 天内）。
- **验收标准**：各筛选项正确过滤对应状态，组合搜索可叠加生效。

#### FR-021 右键上下文菜单

- **优先级**：P1
- **CLI 映射**：复用 FR-006/008/009/011/022/023 对应命令
- **描述**：列表项右键菜单提供：安装（未安装时）/ 升级（可更新时）/ 卸载 / 锁定 / 查看依赖 / 复制包名 / 打开 Homepage。
- **验收标准**：菜单项按包状态动态显隐，动作与对应 FR 行为一致。

#### FR-022 锁定 / 解锁版本

- **优先级**：P1
- **CLI 映射**：`brew pin <formula>` / `brew unpin <formula>`
- **描述**：用户可锁定某个 Formula 版本，使其不参与 `brew upgrade`；锁定状态在列表与详情中展示。
- **验收标准**：
  1. 锁定后包标记为「已锁定」状态。
  2. 已锁定包不进入「全部升级」范围。
  3. 解锁后恢复可升级状态。

#### FR-023 依赖关系展示

- **优先级**：P1
- **CLI 映射**：`brew deps --tree <formula>`、`brew uses --installed <formula>`
- **描述**：详情面板展示依赖树与「被依赖」关系，支持展开/收起。
- **验收标准**：
  1. 依赖树正确展示直接与传递依赖。
  2. 展示「被依赖」包清单。
  3. 展开/收起交互流畅，无循环依赖导致的死循环。

#### FR-024 操作历史 / 日志

- **优先级**：P1
- **CLI 映射**：对 FR-006/007/008/009/011/015/016 的 CLI 输出做落盘记录
- **描述**：记录本地操作历史（时间、命令、结果），供用户查看失败原因与复现。
- **验收标准**：
  1. 每次写操作均生成一条历史记录。
  2. 可查看记录的完整 CLI 输出。
  3. 历史记录持久化于应用本地存储。

#### FR-025 快捷键体系

- **优先级**：P1
- **CLI 映射**：无（UI 导航）
- **描述**：提供全局与列表级快捷键（见 6.5 快捷键映射表）。
- **验收标准**：每个快捷键在其作用范围内触发对应动作，且不与系统/应用既有快捷键冲突。

#### FR-026 系统通知

- **优先级**：P1
- **CLI 映射**：无（对 FR-014 完成事件推送 macOS 通知）
- **描述**：安装/升级/卸载/清理完成后推送系统通知，含结果摘要；可查看失败详情。
- **验收标准**：
  1. 操作完成触发通知，含成功/失败摘要。
  2. 通知可点击跳转到对应页面/日志。
  3. 通知开关可在设置中控制（默认开启）。

#### FR-027 空状态与错误状态处理

- **优先级**：P1
- **CLI 映射**：无（覆盖各 FR 的异常分支）
- **描述**：为所有列表/详情/搜索页面定义空状态、加载失败、权限不足、网络错误的提示与恢复入口。
- **验收标准**：
  1. 空状态展示引导文案（无数据时不空白）。
  2. CLI 执行失败展示可读错误与「重试」入口。
  3. 网络错误展示内联提示条。
